# 生产接入前必须确认的信息

当前完成的是可运行、可恢复的单机参考实现和操作保障；未完成用户真实生产上线验收。以下事项需要实际环境或业务信息，不能靠合成数据代答。

| 必需信息 | 为什么需要 | 接入动作与判据 |
|---|---|---|
| 首个真实源选择、网络地址、表/字段和数据负责人 | MySQL/Hive/StarRocks 的抽取、分区和完整性语义不同 | 选择一个只读导出适配器，确认源水位/行数/批次号，输出 ready 快照；用脱敏样本对账 |
| 省份归属、活跃口径、时区、跨省去重、零活跃和迟到修订规则 | 当前三省、UTC、省内去重、缺省拒绝均为模拟假设 | 业务签署输入输出契约，提供边界样本与期望结果后调整独立 oracle |
| 每日触发时区、数据就绪时刻、交付截止及容忍延迟 | 系统本地08:00与UTC业务日并非天然匹配，未签生产SLA | 配置 launchd 与 deadline_utc_hour，在目标环境执行真实跨日验收与缺输入告警 |
| 运行主机、服务账号、登录/重启策略、源读取与发布消费身份 | 当前同一个可信OS用户、登录域服务不是多用户授权边界 | 以批准的服务账号部署并核对最小目录/数据库权限；需要多人访问时增加认证授权入口 |
| 日数据量、文件大小、增长、保留期、可用磁盘/内存 | 当前CSV和Python sets独立oracle只适合小数据，未做生产容量证明 | 用目标规模脱敏输入压测；不足时迁移Arrow/引擎端校验，必要时PyIceberg/持久catalog |
| 目标RPO/RTO、备份存储与告警值守目的地 | 本机复制不是异地灾备，本地outbox不是已经通知值班人员 | 批准备份目标和外部消息目的地/权限后接入现有监控，演练异机恢复、值守确认和断电 |
| 源凭据交付与密钥托管方式 | 当前没有真实凭据，不应写进SQL/JSON/日志/Git或聊天 | 在目标环境通过批准的secret store注入只读连接器；验证脱敏、轮换与撤销 |

## Iceberg 迁移成本

[PoC](../experiments/iceberg/README.md) 证明无Spark路线可行。当前产品每天只有三行、整日替换、没有跨引擎共享表写入，历史run文件与业务发布指针已满足当前验收。采用Iceberg仍需要本项目的业务审批和交付manifest，不能用单表snapshot代替整个流水线发布。

迁移需要：把候选写入层替换为PyIceberg/PyArrow，定义分区/schema与snapshot生命周期；正式manifest保存table UUID/catalog身份/snapshot ID；实现按快照消费及回滚；选生产catalog/对象存储和凭据；固定引擎与扩展版本并实测兼容，处理旧Parquet历史版本导入与双读切换；重做备份、快照保留/孤儿清理、并发和故障验收。实验环境30包、主环境7包是安装面证据，但决策主要来自当前数据语义，不是因为SQLite或Docker有局限。未来一旦要求标准表快照/schema evolution/跨引擎共享，就应优先采用这条已验证路线。
