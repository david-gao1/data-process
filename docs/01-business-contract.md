# 业务闭环与验收契约

2026-10-15，开发前确立；状态与验证见 [验收报告](evidence/acceptance.md)。

## 目标和模拟假设

企业散落的 SQL、Excel、Python 分析，需要统一可追溯运行和受控交付。第一条业务故事：运营按业务日期生产每日各省活跃用户数，经人工或预先批准的固定版本策略发布后查询截至指定日期最近 30 天趋势。

演示全部使用合成事件；省份仅北京、上海、广东（不是全国覆盖）。按 UTC 日历日期取数；活跃 = 当天至少一次事件，按省份内 user_id 去重。同一用户跨省可分别计数；重复事件不重复计活跃。每个省必须有事件，否则本版拒绝空分区。真实业务的省份、时区、迟到修订、水位、零活跃语义需要业务方确认。

## 输入、输出、边界

输入为上游完成导出的 CSV 快照，严格字段 `business_date,user_id,province`，UTF-8；date 为 ISO 日期，user_id 非空，province 在上述枚举内。一次输入只含一个日期。ready 导入是操作员对“上游已完整导出”的显式确认，入库后按内容 SHA256 固定，不覆盖。平台验证文件完整性与业务质量，不能证明真实上游已抽全。

输出为每个日期恰好三行 Parquet：`business_date VARCHAR,province VARCHAR,active_users BIGINT`。正式查询包含 run_id、release_id、source_id，缺少发布的日期以 missing_dates 返回，不假装为零。任何不合格输入、失败、取消、超时或中断运行都不得发布。

定义是 Git 内 SQL；release 是 SQL + 计算代码 + 依赖锁 + 引擎版本的内容寻址快照；run 是绑定 release、source、date、timeout 的独立实例；delivery 是日期到已验证 run 的原子指针。候选数据不能通过正式查询看到。

每日 trigger 使用 macOS launchd，执行 UTC 昨日固定版本策略；人工 CLI 支持补数和审批。首版为可信本机操作员 CLI，不开放网络端口、不运行用户任意脚本、不连接真实数据源。MySQL/Hive/StarRocks 由未来只读导出适配器转换为本契约；本版不伪造连接器。单机本地磁盘，不支持共享 NFS、多租户、HA、分布式调度。日历定时与保活复用 OS，不实现自制日历调度、自动重试或 DAG，submit 后由单 worker 异步消费。

## 不变量与验收

| ID | 判据 |
|---|---|
| R01 | 源准备 → ready → 提交返回 → 异步运行成功 → 明确审核发布 → 查询得到准确三省统计及 30 天窗口 |
| R02 | 错误日期/空用户/未知省份/缺省/未 ready/篡改输入阻止正式交付 |
| R03 | 同日期重跑，正式指针替换，正式结果不追加、不重复；提交 idempotency key 重复返回同一 run，冲突参数报错 |
| R04 | release 内容不可覆盖；修改定义产生新版本，运行可追溯原始源码、输入 SHA 与引擎版本 |
| R05 | 排队和执行中取消、硬超时均进入终态且不可发布 |
| R06 | worker SIGKILL 后重启核对：遗留 RUNNING 标 INTERRUPTED，排队任务保留；不自动重试，不接管不确定结果 |
| R07 | 发布使用 expected-current-run CAS，防止过期审批覆盖；回滚只允许历史已发布且校验完整的版本，审计记录前后指针和理由 |
| R09 | 每日系统触发固定版本策略，ready 摘要和质量通过才自动发布；重放幂等，人工覆盖后不被旧触发回退 |
| R08 | 损坏候选/正式文件被检测并拒绝；单 worker 锁；备份恢复后可查询且完整性检查通过 |

本机可复现验收是本版底线，不等于真实生产上线通过。真实生产尚需源连接与权限验收、业务口径签字、容量/SLA、备份异机恢复、监控告警和密钥管理。
